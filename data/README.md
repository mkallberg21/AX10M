# BIN table (`bin-table.sample.json`)

`AX10M_BIN_TABLE_PATH` points the feature pipeline at a JSON array of BIN ranges. Each
entry maps a BIN/IIN prefix to card metadata that enriches the recoverability model:

```json
{ "prefix": "424242", "region": "na", "issuerId": "chase", "country": "US", "brand": "visa", "cardType": "credit" }
```

- `prefix` (required) — leading digits of the card BIN. Longest match wins.
- `region` — coarse issuer region (`na` / `emea` / `latam` / `apac` / `unknown`). A **model
  feature**.
- `issuerId` — stable issuer identity. Approval rates aggregate by this (all of an issuer's
  BINs share one learned rate) instead of a raw prefix.
- `country` — ISO 3166-1 alpha-2.
- `brand` — card network.
- `cardType` — `credit` / `debit` / `prepaid`. A **model feature** (prepaid/debit recover
  differently than credit).

## What's shipped here (and what isn't)

`bin-table.sample.json` is a **PUBLIC, network-brand** starter table, generated by
`gen-bin-sample.mjs` from the openly-documented **ISO/IEC 7812** IIN ranges (Visa starts
with `4`, Amex `34`/`37`, Mastercard `51`–`55` + `2221`–`2720`, Discover `6011`/`65`/`644`–
`649`, JCB `35`, UnionPay `62`, Diners `30x`/`36`/`38`/`39`). It fills in **`brand` only**.

It deliberately does **NOT** provide `region`, `issuerId`, `country`, or `cardType` — those
are **not derivable from the network prefix** and require a **licensed commercial BIN
database** (a proprietary, paid dataset that cannot be redistributed here). Those fields are
left `unknown`/absent on purpose; a fabricated value would be worse than an honest gap.

## Plugging in a real (licensed) BIN DB

1. License a commercial BIN/IIN database (issuer-level, with country + product type).
2. Export it to this same `BinRange[]` JSON shape, filling `region`, `issuerId`, `country`,
   and `cardType`.
3. Set `AX10M_BIN_TABLE_PATH=/path/to/your-bin-table.json`.

The loader (`buildFeatureStore`) validates and falls back to the illustrative seed if the
file is missing or malformed. Nothing else changes — the feature store, issuer aggregation,
and the model's card-type feature all consume the richer table automatically.

Regenerate the public starter table with `node data/gen-bin-sample.mjs`.
